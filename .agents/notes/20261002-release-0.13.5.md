## tarball 与发布物一致性

发布轮的仓外 tarball 在 `mktemp -d` 的仓外目录打包（**不是** `pnpm build → npm pack` 旧流程；发布物按 registry 单一渠道口径核对）。本轮复核**重算本地打包产物 + 自 registry 重新下载**两条路径的字节摘要，比对完即删：

| 来源 | 包 | 字节 | 重算 sha256 | 重算 `sha512-base64` | registry `dist.integrity` |
| --- | --- | --- | --- | --- | --- |
| 本地打包 `/tmp/herdsman-0.13.5-prep2/pack/` | `dorokuma-herdsman-0.13.5.tgz` | 214 846 | `590b0a4216abf67699a12f911e9a10f3711110d5485fc712f8fcf9327a28ae73` | `sha512-4HEfcKBCo6RB2dL+lSej+1YNGIQuBjHdD7s+SrFSXwkwgLBka43u29OOwP5KzrIncNJF3iHO9VTtqpwb9oGNGw==` | 同值 ⇒ **一致** |
| 本地打包 `/tmp/herdsman-0.13.5-prep2/pack/` | `dorokuma-herdsman-pi-0.13.5.tgz` | 34 373 | `bb64d26e70b00758030f55b3e3b120f3898a830d2441a92dbcb9af67b6ae722a` | `sha512-2E8nyCplf7hy30DP19KBUT2IW/JtaCOaJRhLzihsa2ZCrcoAqacijL1rqBCRnBYu/ezYVN+xzjNN96MDUUmkDQ==` | 同值 ⇒ **一致** |
| 自 registry 下载 `/tmp/herdsman-registry-0.13.5-verify/herdsman-0.13.5.tgz` | `herdsman-0.13.5.tgz` | 214 846 | `590b0a42…`（同上） | `sha512-4HEfcKBC…`（同上） | 同值 ⇒ **一致** |

`sha256sum` 与 registry 的 `dist.integrity`（base64 sha512，带 `sha512-` 前缀）不可直接比较，按文档用 `printf 'sha512-%s' "$(openssl dgst -sha512 -binary <tgz> | openssl base64 -A)"` **重算整串**后逐字比对。结论：**registry 上的两个发布物与本地打包字节一致**，且 root 包自 registry 重下载后的 sha256 与本地打包产物逐字相同（`590b0a42…`）⇒ 本地打包字节 == registry 发布物字节。

> **复核口径注（避免选错文件）**：`590b0a42…` / `bb64d26e…` 是对**发布后**（README 已 `--ref v0.13.5`）的 pack 产物与 registry 重下载物重算的。`/tmp` 里另有个**发布前**的 pack 目录 `/tmp/herdsman-release-0.13.5.yRi0vq/`，其 root tgz 的 sha256 为 `fe299b3a…`（同 214 846 字节、文件清单与发布物**逐路径相同**，唯一差异是内嵌 `README.md` 仍是 `--ref v0.13.4`）—— 那是 **bump 之前的陈旧 pack**，不是发布物，勿拿它核算。
>
> **判别式只有 root tgz 可用**：该目录里的 **pi tgz 与发布物逐字节相同（sha256 同为 `bb64d26e…`）**，**无法**据此判别新旧；只有 **root tgz 能判别**（陈旧 = `fe299b3a…`，发布物 = `590b0a42…`）。**若该目录日后被清理，以本表的 hash 记录为准。**

## commit-msg 钩子对「文档化脱敏字面量」的误报（本批唯一偏差）

- **现象**：发布提交 `5e02d1d` 的 `commit-msg` 钩子（`.husky/commit-msg` → 全局 `/root/.git-hooks/commit-msg`）在 **staged diff 扫描**（`check_credential_assignments`）时报「appears to contain a hardcoded credential assignment」。命中源是**冻结后的根因笔记文本**：`.agents/notes/20261002-empty-wake-expectedtext-rootcause.md` 里那行**文档化**的脱敏模式清单——以「键名=值」形态出现的凭据字面量（键名含 `Authorization` / token / password / secret / api_key 等；描述 `sanitize-text` 把它们一并换成 `[REDACTED]`）。钩子的正则 `(password|api_key|secret)[[:space:]]*[:=]+[[:space:]]*(.*)` 把其后的说明文字当成凭据值（长度 ≥ 6）**误报**。这不是真实凭据。
- **处置**：用钩子**自带的** `COMMIT_MSG_SKIP_DIFF=1` **只关闭 staged-diff 扫描**（钩子判据 `[ "${COMMIT_MSG_SKIP_DIFF:-0}" != "1" ]`）；**提交信息扫描（`check_secret_patterns` / `check_credential_assignments` on message）与 pre-commit 门禁照常全绿**（lint-staged / typecheck / 847 tests / biome / drizzle 全绿）；**未改文件、未用 `--no-verify`**。并**补偿核验**：按钩子的真实凭据特征（`ghp_`/`gho_`/`ghu_`/`ghs_`/`github_pat_`/`xox[baprs]-`/`sk-`/`AKIA`/`ya29.`/JWT/`-----BEGIN … PRIVATE KEY-----`）复核 staged 新增行，**零命中**。
- **范围边界（易漏，提交前必看）**：钩子扫描**同时覆盖提交信息本身**（`check_secret_patterns` / `check_credential_assignments` 均先对 `RAW_MSG` 跑一遍），所以**别把同类凭据字面量写进 commit message**（否则改完文件仍会被拦）；另外钩子还有**进程噪声词**检查，提交信息里出现「审计 / 审查 / 轮审 / `review round` / `fix audit`」等会被**直接拒绝**（与凭据无关），提交信息措辞要避开。
- **下次遇到同类文档化字面量的建议**：**优先避开「`关键字` + `=` + 值」的字面形态**（例如写成 `password` 与 `=` 之间断开的描述、或用引号/占位包裹使其等价类落进钩子的值白名单），从源头不触发误报；**若确需原文保留**，就沿用 `COMMIT_MSG_SKIP_DIFF=1` **但必须在提交信息或本类笔记里登记这次跳过**，并照做「真实凭据特征零命中」的补偿核验；**不要**用 `--no-verify`（那会连提交信息扫描与 pre-commit 一起关掉），**也不要**为了迁就钩子去改写已冻结的历史笔记内容（违反笔记不可变原则，且误报在文档文本、不在产品改动）。长期更优解是给钩子的值白名单补「文档化占位」形态，但需独立评估、不在本轮。
