## 决策

### 版本判型：patch → **0.14.5**（不是 0.15.0）

- **依据（`docs/releasing.md` 的判据文本）**：版本级递增只在「本批含 breaking change——使用者可感知的东西，例如被移除的公共 API、CLI 命令或行为」时走 minor；该判据的核心是**移除**，不是「行为有任何变化」。本批**没有任何使用者可依赖的能力被移除**：
  - 批次二的两条行为变化都只**移除空内容投递**：①「空轮不再判 `agent.failed`」收窄的是 H1 引入的「degraded `done` 重试耗尽后发一条**可投递** fallback `agent.failed`」，被判掉的轮次本来就**没有可交付正文**，且同一现象由新的按 pane `console.warn`（`reason: upstream_empty_turn`）承接；②「空 `completed` 不投递」移除的是 `last assistant: (no assistant message)` 这条**空正文**唤醒，走静默 ack 收敛投递队列。两者都不减少使用者能拿到的信息量（被移除的正文按定义为空）。
  - 批次一的 `0d176c3` 是**收窄**（把已投递过的旧正文不再当本轮答案第二次投出）+ 扫描上限 200→500；`0011` 是**纯加部分索引**（不改数据、不加删列、不删行）；`bdbce92` 契约冻结在实现上与笔记同口径声明为「纯常量定义 + 字面量替换，行为零变化」。
  - 无公共 API / CLI 命令 / 事件类型被整体移除：`agent.failed` 仍是存在的公共事件（只在「无内容」那一格不再发射），`herdsman` CLI 表面未动，pi 扩展的命令与钩子表面未动。
- **仓库先例（同判据的历史适用）**：minor 只出现在**能力移除**轮——0.13.0（删除 `herdsman daemon start|stop|restart`）、0.14.0（收窄 agent 历史读取支持面、删除五个 reader）；而交付语义类改动一直是 patch——0.14.1（write-off 后 ack、关页隐含消费）、0.14.2（**移除 `HERDSMAN AGENT CONTEXT` 预览块注入**，使用者可感知的注入被删，仍发 patch）、0.14.4（未确认冻结基线的投递判据改动）。本批与 0.14.1/0.14.2/0.14.4 同形，故 patch。
- **反方向理由（为何不选 0.15.0）**：把「任何交付语义变化」都当 minor，会让本仓过去四次同类发布（0.14.1/0.14.2/0.14.4）的判型全部翻盘，且 caret 使用者被要求显式升级的收益为零——被移除的是噪声而非能力。按 `docs/releasing.md` 的「removed public API, CLI command, or behaviour」文本，本批不满足。
- 版本号 `0.14.5` 与 `0.15.0` 在发布前均**不存在于 registry**（两条 `npm view` 均 E404，见下），故不存在版本重发的冲突。
